### Phase 0 — 판정 인바리언트를 테스트로 먼저 고정(레드)

> 판정 산식이 틀리면 **알림이 조용히 거짓말을 한다.** 틀린 값도 알림 형태로는 정상으로 보이므로
> 사람이 알아차릴 수 없다. 그래서 산식을 먼저 테스트로 고정한다.

**작업 내용**:

- [x] 신호 가격 산식 고정 — `전일 종가 × (1 ± 순위 등락률)`, **부등호 방향이 폭등·폭락에서 반대**임을 검증
- [x] **방향별 독립 순위** 고정 — 폭등·폭락 순위를 절대값으로 합치지 않음을 검증
      (합치면 신호가 절반이 되고 한쪽 방향이 구조적으로 묻힌다)
- [x] 근접 판정 고정 — 여유 **1%p**, 도달(동률 포함)과 근접의 경계값 테스트
- [x] 평균대비 정의 고정 — `(현재 ÷ 창 평균 − 1) × 100`, 1·3·5·10년 창. 소수 1자리
- [x] MA 근접도 고정 — `(종가 − SMA200) / SMA200`, 워밍업 구간(200일 미만) 처리
- [x] **부분 성공 금지** 고정 — 티커 하나가 실패하면 전체가 실패함을 검증
- [x] **침묵 조건** 고정 — 신호가 여유 밖이면 발송하지 않음을 검증
- [x] `state/` 파일 스키마 검증 — 잘못된 값에서 예외가 난다. **파일 부재는 둘로 갈린다** —

### Phase 5b — 점검 줄이 세는 기준을 실행으로 통일한다(그린 유지)

> **Phase 5 시안 검토 중 사용자 질문에서 드러난 버그다.** 「미국장 알림은 토요일에도 오고
> 월요일엔 없을 텐데 그 처리는 어떻게 되나」를 확인하다 **예정 횟수가 하루 어긋나 있음**을 찾았다.
>
> | | 무엇을 보나 |
> | --- | --- |
> | `cli.py` 발송 판정 | 실행일의 **전날**이 미국 거래일인가 |
> | `health.py` 예정 횟수 | 실행일 **자체**가 미국 거래일인가 |
> | `health.py` 실제 횟수 | 실행일로 GitHub 실행 이력을 조회 |
>
> **휴장이어도 워크플로는 돌고 조용히 끝나며 성공으로 집계된다.** 그래서 토요일엔 `1/0`,

> `expected_runs` 만 그 원칙을 벗어나 있었다.
>
> 또 하나. `_detail` 이 `try` 로 전체를 감싸고 있어 **워크플로 하나의 조회만 실패해도
> 성공한 나머지 숫자까지 사라지고** `조회 실패` 한 덩어리가 된다. 무엇이 실패했는지 알 수 없다.
