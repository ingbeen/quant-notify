## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

사용자가 매일 아침 네 종목의 근접도 수치를 읽으면서 **매일의 변동폭이 신경 쓰인다.** 매매 판단은 두 선을 넘었는지로만 나므로, 선에서 먼 날의 수치는 판단에 쓰이지 않는 소음이다.

### 확인된 사실 (조사 결과)

| 확인 | 값 |
| --- | --- |
| 매수선 | quant `constants.py:33` `FIXED_4P_BUY_BUFFER_ZONE_PCT = 0.03` → 상단 밴드 `MA × 1.03` |
| 매도선 | quant `constants.py:34` `FIXED_4P_SELL_BUFFER_ZONE_PCT = 0.05` → 하단 밴드 `MA × 0.95` |
| 매수 조건 | `종가 > 상단` 으로 돌파한 뒤 **3일 더** `종가 > 상단` 유지 (quant `buffer_zone.py:379-413`, `FIXED_4P_HOLD_DAYS = 3`) |
| 매도 조건 | `종가 < 하단` 으로 하향 돌파 즉시 (quant `buffer_zone_helpers.py:102`) |
| 등호 방향 | 두 조건 모두 **엄격 부등호** → `p == +3%` 는 돌파가 아니고 `p == -5%` 는 매도가 아니다 |
| Q-2-2XS 의 GLD·TLT | `strategy_id="buy_and_hold"` (quant `portfolio_configs.py:126-139`). 두 선이 적용되지 않는다 |
| 근접도 산식 | `(종가 − SMA200) / SMA200` (`buffer_zone.py:44-62`). `p > 0.03` ⇔ `종가 > MA × 1.03` |
| `_proximity_rows` 호출처 | **직접 1곳** (`buffer_zone.render`) |
| `ProximityLine` 을 만드는 곳 | `cli.py:186-192` 1곳 + 테스트 `test_alert_rendering.py` 2곳 (`:363`, `:592`) |
| 근접도 문자열을 단언하는 테스트 | `test_alert_rendering.py:377-398`(정본 예시) · `test_close_date_guard.py:276`(`+3.98%` 를 네 종목에서 셈) |
| `test_close_date_guard.py` 픽스처 | 근접도 **+3.98%** → 매수선 위라 SPY·QQQ 가 문구로 바뀐다. **그대로 두면 `:276` 이 깨지고, `:278` 의 이동평균 창 검사는 SPY·QQQ 에서 무력해진다** (두 경우 다 `매수선 위` 라 같은 문구) |

### 설계 결정 (2026-09-23 사용자 결정)

- **범위 = 두 선 그대로** (`-5% ≤ p ≤ +3%`). 여유 `m` 을 바깥으로 두는 안(`-7% ≤ p ≤ +5%`)을 기각했다 — 어느 선이든 두 선 사이 8%p 를 지나야 닿으므로 **사전 경고는 두 안이 같고**, 여유가 더 보여주는 것은 **선을 넘은 뒤의 값뿐**이다. 두 선 그대로면 **숫자 ↔ 문구 전환이 곧 돌파·이탈**이다
- **문구 = 위치** (`매수선 위` · `매도선 아래`). 행동 문구(`보유 유지` · `매수 대기`)를 기각했다 — **신호일에 틀린다.** 폭락 매도일에 보유자에게 「매수 대기」가, 돌파 당일에 미보유자에게 「보유 유지」가 나간다
- **GLD·TLT = 매일 수치** (참고용 유지)
- **어느 종목에 선을 적용할지는 상수로 둔다** — `BUFFER_ZONE_SIGNAL_TICKERS = (SPY, QQQ)`. `ProximityLine` 에 필드를 더하는 안보다 diff 가 작고(생성처 3곳 불변), 「어느 종목이 선으로 매매되는가」는 전략 사실이라 `common_constants.py` 가 제자리다
