## 1. ECOS — 원달러 환율 (2026-09-05 실측)

### 1.1 확정된 코드

| 항목 | 값 | 라벨 |

| 통계표 | **`731Y003`** | 3.1.1.3. 원화의 대미달러, 원화의 대위안/대엔 환율 |

### 1.2 왜 이 코드인가 — 비슷한 계열이 넷 있습니다

**여기가 함정입니다.** ECOS 에는 「원달러」로 읽히는 계열이 여러 개이고, **어느 것을 골라도
조회는 성공합니다.** 다른 계열을 고르면 알림 숫자가 조용히 틀립니다.

| 통계표 / 항목 | 라벨 | 2026-08-26 값 |
| --- | --- | --- |
| `731Y001` / `0000001` | 원/미국달러(**매매기준율**) | 1,383.1 |
| **`731Y003` / `0000003`** | **원/달러(종가 15:30)** | **1,384.8** |
| `731Y003` / `0000013` | 원/달러(종가) | 미확인 |
| `731Y003` / `0000002` · `0000004` · `0000005` | 시가 · 저가 · 고가 | — |

`reference/원달러_백분위_알림.md` §1.2 가 **"원달러 정규장 종가"** 를 쓴다고 못박았고,
15:30 은 정규장 마감 시각입니다. **매매기준율은 전일 은행간 거래의 가중평균이라 다른 값**입니다.

### 1.3 계산 경로 검증 — 정본과 대조했습니다

정본 문서 §5.1 의 2026-08-26 기준 실측값과 맞춰봤습니다.

| 항목 | 이 저장소 | 정본 문서 | 판정 |
| --- | ---: | ---: | --- |
| 현재값 | 1,384.8 | 1,384.80 | **일치** |
| 1년 평균 | 1,462 | 1,462 | **일치** |
| 1년 평균대비 | **-5.3%** | -5.3% | **일치** |
| 3년 평균 | 1,404 | 1,404 | **일치** |
| 3년 평균대비 | **-1.3%** | -1.3% | **일치** |
| 5년 평균 | 1,352 | 1,351 | 1원 차 |
| 5년 평균대비 | **+2.5%** | +2.5% | **일치** |

**알림에 나가는 숫자(평균대비)가 세 창 모두 소수 1자리까지 같습니다.**

`731Y001/0000001`(매매기준율)로 같은 계산을 하면 현재값이 **1,383.1** 이고 1년 평균대비가
**-5.4%** 로 어긋납니다. 조회는 똑같이 성공하므로 **대조하지 않으면 알아차릴 수 없습니다.**

### 1.4 창 경계는 양끝을 포함합니다

거래일 수가 1개씩 어긋나 확인한 결과, 정본 §5.2 검산이 **"2025-08-26 ~ 2026-08-26, 246 거래일"**
로 **시작일을 포함**합니다. 시작일을 빼면 245일이 되고 5년 평균이 1원 어긋납니다.

**창을 자를 때 `start <= 날짜 <= end` 로 양끝을 포함합니다.**

### 1.5 응답 시간

| 조회 | 행 수 | 시간 |
| --- | ---: | ---: |
| 10년치 (`2016-09-07 ~ 2026-09-05`) | 2,460 | **0.76초** |
| 11년치 (`2015-01-02 ~ 2026-08-26`) | 2,861 | 1초 미만 |

워크플로 제한 시간에 걸릴 여지가 없습니다. 계획서가 우려한 항목은 해소됐습니다.

### 1.6 인증키 취급

인증키가 **URL 경로**에 들어갑니다. 두 가지로 막았습니다.

- 로거에 마스킹 필터를 걸어 **모든 로그**가 자동으로 가려집니다 (`utils/logger.py`)
- `requests` 예외를 그대로 올리지 않고 **마스킹한 메시지로 바꿔** 다시 냅니다.
  `requests` 예외 문자열에는 요청 주소가 담깁니다

`.env` 는 `dotenv_values` 로 값만 읽고 `os.environ` 에 올리지 않습니다 — 올리면 이후
실행되는 모든 하위 프로세스가 키를 상속받습니다.

**한 달력으로 두 시장을 판정하면 이런 날 알림이 어긋납니다.** 미국 노동절에 한국 역방향
알림이 빠지거나, 한글날에 미국 알림이 빠집니다.

### 3.2 달력이 다루는 범위

**2006-09-05 ~ 2027-09-03** — 앞으로 **약 1년**까지만 커버합니다.

범위를 벗어난 날짜를 물으면 **예외를 냅니다.** 조용히 `False` 를 돌려주면 알림이 통째로
빠진 것을 휴장으로 오해하게 됩니다. 예외 메시지가 `exchange-calendars` 갱신을 가리킵니다.

> **운영 주의**: 라이브러리를 1년 넘게 갱신하지 않으면 어느 날 알림이 예외로 실패합니다.
> 실패 알림이 오므로 조용히 죽지는 않습니다.

### 3.3 알려진 경고

`exchange_calendars` 4.13.2 가 NumPy timedelta 관련 `DeprecationWarning` 을 냅니다.
**라이브러리 내부 문제이고 판정 결과에는 영향이 없습니다.** `pytest.ini` 가
`DeprecationWarning` 을 표시만 하고 실패시키지 않아 검증은 통과합니다.

## 4. pykrx — 준비 상태만 확인 (2026-09-05, 장 마감 후)

**장중 판정은 아직입니다.** 토요일이라 두 소스 모두 직전 거래일 값만 돌려줍니다.
다만 준비 과정에서 확인한 것 둘을 남깁니다.

### 4.1 `.env` 값은 환경 변수로 올려야 pykrx 에 닿습니다

pykrx 는 **가져오는 시점에 로그인을 시도**하고 자격증명을 **환경 변수에서만** 읽습니다.
`.env` 파일에 값이 있어도 그대로는 닿지 않아 `KRX 로그인 실패` 가 뜹니다.

그래서 `scripts/probe_intraday.py` 는 pykrx 를 가져오기 **전에** `.env` 의 `KRX_` 값을
환경 변수로 올립니다. 이렇게 하면 로그인이 됩니다(만료 1시간).

> ECOS 인증키와는 반대 방침입니다. ECOS 는 값으로만 다뤄 환경 변수를 오염시키지 않지만,
> pykrx 는 그 방식만 읽으므로 선택지가 없습니다.

### 4.2 pykrx 가 로그인 정보를 표준출력에 찍습니다

로그인에 성공하면 pykrx 가 **`로그인 ID: <아이디>` 를 직접 출력**합니다.
라이브러리가 stdout 에 쓰는 것이라 **이 저장소의 로거 마스킹이 걸리지 않습니다.**

퍼블릭 저장소는 Actions 실행 로그가 공개되므로 **KRX 계정 아이디가 로그에 남습니다.**
비밀번호는 찍히지 않고 아이디만으로 로그인할 수는 없어 심각도는 낮지만, 알고 두는 것과
모르고 두는 것은 다릅니다.

**로그인이 실제로 필요한지부터 가립니다.** 장중 조회가 로그인 없이 된다면 `KRX_ID`·`KRX_PW`
자체를 쓰지 않으면 되고, 그러면 이 문제가 사라집니다. 필요하다면 워크플로에서 pykrx 호출
구간의 표준출력을 눌러야 합니다.

### 4.3 로그인 없이도 과거 일봉은 조회됩니다 (2026-09-06 실측)

`KRX_ID`·`KRX_PW` 를 올리지 않고 부르면 **`KRX 로그인 실패` 가 뜨지만 조회는 성공합니다.**

```
KRX 로그인 실패: KRX_ID 또는 KRX_PW 환경 변수가 설정되지 않았습니다.
조회 행 수: 5        (2026-08-31 ~ 09-04, 069500)
```

**장중 현재가도 그런지는 아직 모릅니다.** 그것이 월요일 실측의 항목입니다.

### 4.4 pykrx 와 yfinance 의 KODEX 일봉 종가가 같습니다 (2026-09-06 실측)

| 날짜 | pykrx | yfinance `069500.KS` | 차이 |
| --- | ---: | ---: | ---: |
| 2026-08-31 | 107,615 | 107,615.00 | **0.00** |
| 2026-09-01 | 107,885 | 107,885.00 | **0.00** |
| 2026-09-02 | 103,500 | 103,500.00 | **0.00** |
| 2026-09-03 | 103,610 | 103,610.00 | **0.00** |
| 2026-09-04 | 105,720 | 105,720.00 | **0.00** |

2026-08-31 의 107,615 는 `reference/역방향_매매_규칙.md` §1.5 가 적은 종가와 **일치합니다.**
주간 알림의 지난주 역방향 요약을 yfinance 로 받아도 정본과 어긋나지 않습니다.

> 같은 문서 §1.5 는 그 날 **장중 마지막 5분봉이 106,645** 였다고 적었습니다. 실측에서도
> yfinance 1분봉 마지막(14:59)과 확정 종가가 달랐습니다 — **동시호가에서 움직입니다.**
> 장중 값은 언제나 「가능성」이고 확정은 종가로만 됩니다.

### 4.5 yfinance 는 KODEX 200 분봉을 줍니다

`069500.KS` 를 `interval="1m"` 으로 받으면 분봉이 옵니다. 실측 시점에 마지막 봉은
**2026-09-04 14:59 KST · 106,075** 였습니다. 정규장 마감 직전 봉입니다.

**장중에도 봉이 갱신되는지는 아직 모릅니다.** 그것이 월요일 실측의 핵심입니다.

## 5. 장중 시세 소스를 yfinance 로 정했습니다 (2026-09-06 결정)

한국 역방향은 **장중 12:00 · 14:30 에 현재가**를 봅니다. 두 후보 중 yfinance `069500.KS`
1분봉을 씁니다. **pykrx 는 쓰지 않습니다.**

### 5.1 왜 yfinance 인가

| 근거 | 내용 |
| --- | --- |
| 값이 이미 검증됨 | 일봉 종가가 pykrx 와 **5일 전부 차이 0.00** (§4.4). 2026-08-31 의 107,615 는 정본 §1.5 실측값과 일치 |
| 분봉이 실제로 옴 | §4.5 에서 확인 |
| **자격증명이 필요 없음** | pykrx 는 가져오는 시점에 로그인하며 **계정 아이디를 표준출력에 찍습니다** (§4.2). 퍼블릭 저장소는 Actions 로그가 공개라 이것을 눌러야 하는데, `redirect_stdout` 은 라이브러리 동작에 기대는 방어입니다. yfinance 는 그 문제와 시크릿 두 개가 통째로 사라집니다 |
| 코드 재사용 | `data/yfinance_client.py` 가 이미 있습니다 |

### 5.2 1분봉이 14:59 에서 끊깁니다 (2026-09-06 관측)

| 무엇 | 값 | 시각 |
| --- | --- | --- |
| 1분봉 마지막 | 106,075 | 2026-09-04 **14:59** KST (360봉) |
| 일봉 종가 | 105,720 | 2026-09-04 |

한국 정규장은 **15:30** 까지인데 1분봉은 14:59 에서 끝나, 마지막 31분이 빠져 종가와
**355원(0.34%) 차이**가 납니다. 판정 시각(12:00 · 14:30)이 둘 다 14:59 보다 앞이라
당장은 걸리지 않지만, **이것이 지연인지 제공 범위 제한인지 아직 모릅니다.**

**장중 실측으로 가려야 합니다.** 지연이면 14:30 판정이 그만큼 과거 값을 보게 되고,
역방향 「도달」이 늦게 잡힙니다. `scripts/probe_intraday.py` 가 pykrx 와 나란히 재도록
돼 있습니다.

### 5.3 장중에는 일봉에 당일 봉이 섞여 옵니다

전일 종가를 **위치가 아니라 날짜로** 골라야 합니다. 장중에 일봉을 받으면 당일 미확정
봉이 마지막에 오는데, 그것을 전일 종가로 쓰면 신호 가격이 통째로 어긋나고 **알림
형태로는 정상으로 보입니다.** `yfinance_client.previous_close` 가 이 일을 합니다.
